# Adriana L. Ruiz-Rizzo: research website

This is the personal website of Dr. Adriana L. Ruiz-Rizzo, cognitive and clinical neuroscientist
at the Department of Neurology, Jena University Hospital. It presents her research, publications,
methods, career and contact details, and is published at <https://alruizzo.github.io>.

The site is built with Quarto from the Markdown pages and YAML data files in this repository.

## Commands

| Task | Command |
|---|---|
| Install the build dependency (once) | `pip install -r requirements.txt` |
| Build the whole site, with all checks | `quarto render` |
| Live preview while editing | `quarto preview` |
| Test the build checks | `python3 -m unittest discover -s scripts -p 'test_*.py'` |
| Rewrite the footer icon row (after editing `data/profiles.yml`) | `python3 scripts/prerender.py --write-footer` |
| Regenerate the hero network (after changing its layout or colors) | `python3 scripts/make_motif.py` |
| Redraw link-preview images (after a title or description change) | `pip install -r requirements-dev.txt`, then `python3 scripts/make_social_cards.py` |

`quarto render` is the one-command build. It runs `scripts/prerender.py` first (validates every
data file and regenerates the BibTeX export) and `scripts/check_site.py` last (fails on broken
internal links or anchors, images without alt text, and listings whose rendered item count
differs from the data). Either failing stops the build. Output goes to `_site/` (not committed).

Requirements: Quarto 1.10.18 (the CI version) and Python 3.10 or newer.

## Content data

Repeated content is never hand-written HTML. Each page section that lists items is a Quarto
listing over a YAML file, rendered by a template in `_templates/`:

- **Publications** (`data/publications.yml`). Required: `id`, `type`, `title`, `year`, `date`.
  `type` is one of `article`, `chapter`, `preprint`, `abstract`, `thesis`, `scicomm`.
  `categories` holds research themes (exact names, see `THEMES` in `scripts/prerender.py`); `theme`
  is the slug of the first one. `featured: true` puts an entry on the homepage (1 to 4 entries,
  each needs a `summary`). `data` lists open data links, each of which must have a record in
  `outputs.yml`. `source` records provenance (see below). Unknown fields fail the build.
- **Outputs** (`data/outputs.yml`): `related` names the publication an output accompanies; the
  validator checks the link both ways.
- **Career and recognition**: `highlight: true` (with a `short` label for career entries) shows
  an item in the homepage credentials strip. `fellowship: true` (with `summary` and `funders`)
  features a recognition entry in the homepage fellowships section.
- **Funders** (`data/funders.yml`): a funder with `logo` needs `logo_alt` and `logo_source`; a
  funder without one renders as a text wordmark, and `logo_status: pending` makes the build warn.
- **Generated data** (`data/generated/`): listings cannot join files, so `prerender.py` writes
  recognition records with their funders inlined, and the co-author list: everyone with three or
  more joint articles, chapters or preprints, "current" when the last joint work is from 2023 on.
  Name variants that accent and hyphen folding cannot join go in `coauthor-aliases.yml`.

To add a paper: append a record to `publications.yml` (copy an existing one), run `quarto render`,
and read the prerender summary it prints.

## Design system

- **Color**: every color is sampled from Fabio Crameri's
  [Scientific Colour Maps](https://www.fabiocrameri.ch/colourmaps/) (v7.0,
  doi:[10.5281/zenodo.4491293](https://doi.org/10.5281/zenodo.4491293)), perceptually uniform and
  readable with color-vision deficiencies. Neutrals come from `grayC`, the hero's warm highlights
  from `batlow` (the hero ground itself is the original ink `#16132B`, restored by choice), the interactive accent from `acton`, and each research theme from its
  own map (`devon`, `batlow`/`hawaii`, `bilbao`/`turku`, `bamako`/`tokyo`, `hawaii`/`lajolla`,
  `grayC`), at a dark point for light mode and a light point of the same hue family for dark mode.
  Each token is annotated with its map and index in `styles/light.scss` and `styles/dark.scss`.
  Theme color is always paired with the theme's name.
- **Contrast**: every text element on every page was measured in the browser against its actual
  background in both themes; all pass WCAG AA (body text 4.5:1, large text 3:1). Re-measure after
  changing a token.
- **Type**: system serif (New York, Iowan Old Style, Charter, Georgia) for display headings, system
  sans for text, a modular scale of about 1.25, 17 px body, tabular figures for years and numbers,
  measure limited to about 68 characters.
- **Layout**: neutral surface ladder (page, band, card) separated by background steps and hairlines;
  no accent side bars. Responsive down to 375 px without horizontal scrolling.
- **Theme toggle**: a moon in light mode and a sun in dark mode, showing what a click will do, with
  a matching label ("Switch to dark mode" / "Switch to light mode") and a button role.
- **Accessibility**: skip link, landmarks, visible focus rings, real buttons for the theme filter
  (with `aria-pressed`), alt text on all images, `prefers-reduced-motion` honored. Core content
  works without JavaScript; the theme filter appears only when it can work.
- **Motion**: the homepage hero has a staged entrance and a
  living network behind it: a slow drift, hub nodes that breathe and faint warm signals travelling
  along a few connections. One pause button stops all of it (WCAG 2.2.2); without JavaScript or
  under `prefers-reduced-motion` the network is static and the signals are hidden.
- **Privacy by construction**: no cookies, analytics or third-party requests (MathJax is disabled
  because the site has no mathematics). `check_site.py` fails the build if a page loads anything
  from another host, because the privacy statement relies on it.

## Profiles in the footer and on Contact

`data/profiles.yml` lists the e-mail address and each scholarly profile once, with its icon. The
Contact page renders the list from it, with the icon as each item's bullet. The footer icon row
(icon above the network's name) is written into `_quarto.yml` by
`python3 scripts/prerender.py --write-footer`. The build fails when the footer, `_variables.yml`
links, the icon files or their CSS rules disagree with `profiles.yml`, and `check_site.py` confirms
every rendered page carries the same footer row. Icons are CSS masks, so they follow the theme
colors, need no JavaScript and fall back to the system text color in high-contrast mode.

## Link previews

When a page is shared in a messenger, on a social platform or by e-mail, the preview card comes
from these tags, all verified per page by `check_site.py`:

- **Open Graph**: `og:title`, `og:description`, `og:url`, `og:type` (`profile` on About, with
  `profile:first_name` and `profile:last_name`), `og:site_name`, `og:locale`, and `og:image` with
  width, height, type and alt text. Plus `<link rel="canonical">`.
- **Twitter/X**: `summary_large_image` with title, description, image and alt text matching the
  Open Graph values, and `twitter:creator`.
- **Images**: each page has its own 1200 by 630 PNG in `assets/social/` (under 300 KB), drawn from
  the page's title and description by `scripts/make_social_cards.py`. Text stays inside the area
  that survives the 2:1 crop some apps apply.
- **Content stays current**: titles and descriptions come from each page's front matter
  (`share-card-title`, `share-card-tagline`, `open-graph`/`twitter-card` overrides where a page
  needs them). The build fails when a page has no card, when a card no longer matches its page,
  when a description exceeds 160 characters, or when a tag is missing, duplicated or inconsistent.
  The 404 page is `noindex` and declares no canonical URL.

To add a page: give it a `title` and `description`, add it to `PAGES` in
`scripts/make_social_cards.py`, run that script, and set `image: assets/social/<page>.png` and
`image-alt` in its front matter.

## Deployment

`.github/workflows/publish.yml` tests, renders and deploys `_site/` to GitHub Pages on every push
to `main` (pull requests build and check only). In the repository settings, set Pages to deploy
from **GitHub Actions**. Publishing Pages from a private repository requires a paid GitHub plan.
`site-url` in `_quarto.yml` is `https://alruizzo.github.io`, a GitHub user site served from the root,
so the repository that deploys it must be `alruizzo/alruizzo.github.io`. If the address changes,
update `site-url`, `SITE_URL` in `scripts/check_site.py`, `SITE_LABEL` in
`scripts/make_social_cards.py` (then redraw the cards) and the URLs in the JSON-LD of `index.qmd`.
External links are checked weekly by `.github/workflows/external-links.yml`, as a warning only.
